# Escape

정적 HTML/CSS/JavaScript 방탈출 보조 웹입니다. 메인에서 컨셉을 선택하면 모든 페이지에 같은 테마가 적용됩니다. 두 컨셉은 동일한 레이아웃과 CSS 변수를 사용합니다.

## 실행 및 진행
`python -m http.server 8000`으로 실행한 다음 http://localhost:8000 에 접속합니다.
게임 시작 → 현장의 문제 키로 필요한 힌트 조회 → 진행자가 비밀번호로 종료 → 닉네임 등록.
게임 방법은 플레이 화면의 팝업에서 사이트 이용 / 자물쇠 이용 안내를 한 화면에 함께 보여줍니다. 팝업은 `guide.html?embed=1`을 iframe으로 보여주며, 열어 둔 동안에도 시간은 흐릅니다.
홈의 순위표 링크(`ending.html?view=leaderboard`)는 기록 입력 없이 순위만 보여줍니다. 종료 후 이동하는 `ending.html?view=result`에서만 완료된 게임의 기록을 등록할 수 있습니다.
게임 화면을 새로고침하면 이어집니다. 메인의 게임 시작을 누르면 선택한 컨셉의 시간, 문제 진행, 힌트가 초기화되어 새 게임이 시작됩니다. 등록한 순위표 기록과 다른 컨셉의 진행은 유지됩니다.
타이머는 페이지가 닫힌 시간도 포함하며, 힌트는 문제별 최초 열람에만 600초(10분)를 더합니다.
두 컨셉의 진행과 리더보드는 각각 저장됩니다. 기존 `the_escape_records` 데이터는 삭제하지 않으며, 컨셉을 알 수 없어 새 순위표에 자동 편입하지 않습니다.

## 예시 문제 수정
게임 화면의 엔딩 바로가기는 비밀번호 `1234`로 현재 시간을 확정하고 기록 등록 화면으로 이동합니다. 비밀번호는 `js/ending-shortcut.js`에서 바꿉니다. 이는 현장 진행용 UI 잠금이며 소스가 공개되는 정적 웹의 서버 인증 기능은 아닙니다.

`js/problem.js`의 `puzzleSets`에서 `key`, `title`, `hints`를 바꿉니다. `hints`는 일반적인 단서부터 구체적인 풀이 순서로 작성하는 힌트 문자열 배열입니다. 배열의 길이에 따라 팝업의 단계 수가 결정됩니다. key는 숫자 세 자리 문자열로 컨셉 내에서 고유하게 지정합니다. 양 끝 공백은 무시하며, 앞의 0은 유지합니다. 현재 컨셉에 속한 문제만 조회하며 웹에서 정답을 판정하지 않습니다.

운영용 키와 힌트는 `js/problem.js`에서 확인합니다. 모든 키는 처음부터 순서에 관계없이 조회할 수 있습니다.
원형 게이지는 힌트 추가 시간을 포함한 표시 시간을 기준으로 90분에 가득 찹니다. 90분이 지나도 게이지는 100%를 유지하며, 시간은 계속 측정합니다.

| 컨셉 | 문제 1 | 문제 2 | 문제 3 | 문제 4 | 문제 5 |
| --- | --- | --- | --- | --- | --- |
| 저주받은 인형 | 10 | 0314 | 솔 | 인형 | 1357 |
| 옛 은신처 | 25 | 917 | 동쪽 | 12 | 8642 |

## 공용 리더보드: Supabase 설정

게임 진행·타이머는 이 브라우저의 localStorage에 유지하고, 리더보드 기록은 Supabase에만 저장합니다. 설정 전이나 네트워크 오류 시 로컬 순위표로 자동 전환하지 않습니다. 기존 `escape_records_*` 로컬 기록은 삭제하지 않지만 공용 순위표로 자동 업로드하지 않습니다.

### 1. DB 생성

1. Supabase 프로젝트를 만듭니다.
2. SQL Editor에서 `supabase/schema.sql`을 **처음 한 번** 실행합니다. 테이블이 이미 존재하면 먼저 구조를 검토하세요. 기존 테이블을 삭제하는 스크립트가 아닙니다.
3. `supabase/verify-policies.sql`을 실행해 비로그인·일반 계정 등록 허용, 입력 검사, 수정·삭제 차단을 확인합니다. 이 검사는 임시 사용자와 기록을 만든 뒤 모두 롤백합니다.

이미 이전 버전의 `schema.sql`을 실행했다면 **`supabase/allow-public-registration.sql`을 실행**하세요. 기존 기록과 직원 계정을 유지하면서 로그인 없는 등록을 허용합니다. 기존 프로젝트에 `schema.sql`을 다시 실행하지 마세요.

`escape_records`는 컨셉별로 조회하고, 최종 시간 → 등록 시각 → 게임 ID 순서로 정렬합니다. 페이지 단위로 요청하므로 Supabase의 기본 조회 행 제한에 의해 전체 순위표가 잘리지 않습니다. `created_at`과 `staff_id`는 DB에서 채우며 웹에서 지정할 수 없습니다. 직원 ID는 공개 조회 대상에서 제외합니다.

로그인 기능은 제거했습니다. 기존 DB의 직원 계정·테이블은 호환성을 위해 그대로 두며, 사이트에서는 사용하지 않습니다. 기록 수정·삭제는 Supabase 관리자 화면에서 처리합니다.

### 2. 공개 연결 설정

`js/supabase-config.js`에 프로젝트 URL과 **새 publishable key**를 입력합니다.

```js
window.ESCAPE_SUPABASE = Object.freeze({
  url: 'https://프로젝트-ID.supabase.co',
  publishableKey: 'sb_publishable_공개용키'
});
```

이 두 값은 public repo에 올려도 됩니다. 직원 비밀번호, `sb_secret_...`, `service_role`, DB 접속 비밀번호는 입력하지 않습니다. 프런트엔드에 포함된 값은 GitHub Secrets로 빌드해도 브라우저에서 보입니다. 현재 구현은 `sb_publishable_` 키만 받습니다.

Supabase JS SDK 2.49.1을 CDN에서 로드합니다. 기존처럼 GitHub Pages에 정적 파일을 배포하면 되며 별도 빌드나 서버 프로세스는 필요하지 않습니다. Supabase 서비스와 CDN에 접근할 수 있는 인터넷 연결이 필요합니다.

### 3. 운영 흐름

- 직원 로그인 없이 홈에서 바로 게임을 시작하고 기록을 등록할 수 있습니다. 별도의 계정이 필요하지 않습니다.
- 게임 종료 → 기록 입력 팝업 → DB 저장 성공 → 공용 리더보드
- 기록 입력 팝업에는 직원 로그인 버튼을 표시하지 않으며, 로그인 여부를 검사하지 않습니다.
- 저장 실패 시 팝업을 유지합니다. 같은 게임 ID로 다시 등록해도 중복 기록은 생기지 않습니다.
- 홈의 순위표는 로그인 없이 볼 수 있습니다. 목록 조회 실패 시 **다시 시도**를 누릅니다.

닉네임·기록 시간·등록 시각은 공개됩니다. 실명이나 연락처 대신 닉네임을 사용하세요. 누구나 API로 기록을 등록할 수 있으며 허위·대량 등록 방지는 구현하지 않습니다. 시간 계산은 브라우저에서 이루어지고 서버에서 실제 탈출 시간을 검증하지 않습니다. 수정·삭제는 계속 Supabase 관리자 화면에서만 처리합니다.

node --test tests/*.test.cjs
