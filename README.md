# Escape

정적 HTML/CSS/JavaScript 방탈출 보조 웹입니다. 메인에서 컨셉을 선택하면 모든 페이지에 같은 테마가 적용됩니다. 두 컨셉은 동일한 레이아웃과 CSS 변수를 사용합니다.

## 실행 및 진행
`python -m http.server 8000`으로 실행한 다음 http://localhost:8000 에 접속합니다.
게임 시작 → 현장의 문제 키로 필요한 힌트 조회 → 진행자가 비밀번호로 종료 → 닉네임 등록.
게임 방법은 플레이 화면의 팝업에서 사이트 이용 / 자물쇠 이용 탭으로 확인합니다. 팝업은 `guide.html?embed=1`을 iframe으로 보여주며, 열어 둔 동안에도 시간은 흐릅니다.
홈의 순위표 링크(`ending.html?view=leaderboard`)는 기록 입력 없이 순위만 보여줍니다. 종료 후 이동하는 `ending.html?view=result`에서만 완료된 게임의 기록을 등록할 수 있습니다.
게임 화면을 새로고침하면 이어집니다. 메인의 게임 시작을 누르면 선택한 컨셉의 시간, 문제 진행, 힌트가 초기화되어 새 게임이 시작됩니다. 등록한 순위표 기록과 다른 컨셉의 진행은 유지됩니다.
타이머는 페이지가 닫힌 시간도 포함하며, 힌트는 문제별 최초 열람에만 600초(10분)를 더합니다.
두 컨셉의 진행과 리더보드는 각각 저장됩니다. 기존 `the_escape_records` 데이터는 삭제하지 않으며, 컨셉을 알 수 없어 새 순위표에 자동 편입하지 않습니다.

## 예시 문제 수정
게임 화면의 엔딩 바로가기는 비밀번호 `1234`로 현재 시간을 확정하고 기록 등록 화면으로 이동합니다. 비밀번호는 `js/ending-shortcut.js`에서 바꿉니다. 이는 현장 진행용 UI 잠금이며 소스가 공개되는 정적 웹의 서버 인증 기능은 아닙니다.

`js/problem.js`의 `puzzleSets`에서 key, title, hint를 바꿉니다. key는 컨셉 내에서 고유하게 지정합니다. 키 입력은 대소문자와 양 끝 공백을 구분하지 않습니다. 기존 description과 answer는 현장 문제 구성용 참고 데이터이며 웹에서 정답을 판정하지 않습니다.

예시 키: 저주받은 인형 `D01`~`D05`, 옛 은신처 `H01`~`H05`. 모든 키는 처음부터 순서에 관계없이 조회할 수 있습니다.

| 컨셉 | 문제 1 | 문제 2 | 문제 3 | 문제 4 | 문제 5 |
| --- | --- | --- | --- | --- | --- |
| 저주받은 인형 | 10 | 0314 | 솔 | 인형 | 1357 |
| 옛 은신처 | 25 | 917 | 동쪽 | 12 | 8642 |

## 외부 리더보드 제안: Supabase
현재 외부 전송은 연결하지 않았습니다. Supabase 데이터베이스와 REST API를 쓰면 별도의 상시 서버 없이 공용 순위표를 만들 수 있습니다.

1. `escape_records` 테이블에 id(UUID 기본 키), concept(doll/hideout), nick(1~12자), total_sec(0 이상 정수), penalty, created_at을 만듭니다.
2. 공개 순위 조회는 RLS 정책으로 SELECT만 허용합니다. concept 필터와 total_sec 오름차순, created_at 오름차순으로 조회합니다.
3. 등록은 Edge Function의 POST 엔드포인트로 받고, 입력 검사·요청 제한 후 저장합니다. id를 고유 키로 사용해 재전송 시 중복을 방지합니다. 서비스 비밀 키는 함수에만 보관합니다.
4. `js/app.js`에서 로컬 저장 성공 후 동일 기록을 POST합니다. 실패 시 로컬 기록을 유지하고 별도의 재전송 상태와 버튼을 제공합니다.
5. 목록은 서버에서 다시 조회하며, 네트워크 장애 시 “이 기기 기록”으로 명확하게 표시해 로컬 목록을 보여줍니다.

단순 수집만 필요하면 Google Forms에 닉네임·컨셉·탈출 시간을 제출하는 방식도 가능하지만, 이 페이지 안의 공용 순위표까지 만들려면 Supabase가 적합합니다.

현재 시간과 종료 판정은 클라이언트에 있으므로 기록을 조작할 수 있습니다. 공정한 공개 대회용이라면 시작 시각·완료 판정을 서버에서도 관리해야 합니다.
